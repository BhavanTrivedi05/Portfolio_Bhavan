Cosmos

Aug 2026 to now

Motorsport news and community platform, my own

A news reader for every racing series. Every minute a scheduler checks which of ten feeds is due, fetches it, and merges the same headline from different outlets into one story with PostgreSQL trigram matching. Race calendars cover F1, MotoGP, IndyCar, and WEC, readers react to stories Reddit-style, and every page is rendered on the server.

Every request passes through CyberGuard, the security layer at its core: security headers, IP blocking, rate limiting, SQL injection and XSS checks, CSRF protection, and JWT access rules, in that order. CyberGuard began as a separate gateway project of mine, so before building on it I audited it. I found eight defects, among them a credential committed to the repo, a path to taking over an admin account, passwords stored in plaintext, and a rate limiter that never limited anything. I fixed them one at a time with Claude Code, and the test suite decided what stayed.

It’s built to run lean on one small server. I measured what a container would cost in memory against the 1 GB I’ll have, then set it up under systemd behind Caddy instead, with the deploy runbook already written. Automated accessibility checks run in CI, because I want blind and low-vision fans to be able to use it with a screen reader.

Strata

Nov 2026 to now

Sharded, replicated key-value store, graduate coursework with one teammate

A key-value store that runs across many machines and stays correct when they fail. Keys hash into 1,024 slots, a controller that is itself replicated maps slots to groups, and each group keeps three copies of its data on three different machines, kept in step by Raft. Writes reach a write-ahead log before they’re acknowledged, so a crash can’t lose them. We’re writing it in C++17 with only the standard library, for Building Scalable Distributed Systems (CS 6650).

My half is the client side and the harness that tries to break everything else: the TCP RPC layer, a deterministic simulator that runs every node in one process with a fake network, disk, and clock, so any failing run replays exactly from its seed, a linearizability checker, the client library, the fault scripts, and a live Prometheus and Grafana dashboard. Once the core passes, I build transactions that span shards, with two-phase locking and two-phase commit. My teammate owns storage, Raft, and the servers, and we review each other’s code.

SpendWise

May 2025 to now

Personal finance app, being rebuilt as a product of my own

Expenses, accounts, categories, and vendors, with filtered reporting, a dashboard, and exports. Every query checks ownership, so an account only ever reads its own rows. Roles keep admins and users apart, passwords are hashed with BCrypt, and password recovery works through a one-time code sent by email.

It began as the expense platform I built during my internship, and I’m turning it into a product of my own. It runs on PostgreSQL with Flyway migrations and optimistic locking, behind about 270 tests. When I reviewed it again in October, I found real problems, from money stored as floating point to a race in password-reset attempts, and I’m fixing them one at a time, each with its own test.
